# ux-reviewer 누적 경험치

이 파일은 `ux-reviewer` 역할이 kiorder 화면을 검토하며 축적한 지식이다. 매 작업 시작 시 읽고, 새로 배운 것을 아래에 이어서 기록한다.

## 환경 세팅 (매번 다시 알아내지 말 것)

- dev 서버가 이미 떠 있을 수 있다. `curl -sf http://localhost:3000`으로 먼저 확인하고, **내가 띄우지 않은 서버는 죽이지 않는다**
- Playwright 스크립트는 반드시 `frontend/` 안에 만들어야 `playwright` 모듈이 해석된다. 스크래치 디렉토리에 두면 `ERR_MODULE_NOT_FOUND`
- 로그인: `#email` / `#password` / `button[type="submit"]` → `**/owner/dashboard**` 대기(백엔드 Render 콜드스타트로 최대 90초)
- **텍스트 selector 주의**: 모바일/태블릿/PC 마크업이 동시에 DOM에 있고 CSS로만 숨겨져서 `text=메뉴 관리` 같은 건 strict mode 충돌이 난다. `h1:has-text(...)`, `nav button:has-text(...)`, `.first()`/`.last()`를 쓸 것
- 작업 끝나면 임시 `.mjs` 삭제

## 환경 세팅 추가 팁 (2026-08-05 2차 리뷰에서 발견)
- `frontend/.env`의 `NEXT_PUBLIC_BACKEND_URL`은 배포된 Render 백엔드를 가리킨다. **백엔드 코드를 수정했는데 아직 배포/커밋 전이라면**, 로컬 백엔드(`backend/`, `npm run start:dev`, 기본 포트 3001)를 띄우고 `frontend/.env.local`에 `NEXT_PUBLIC_BACKEND_URL='http://localhost:3001'`을 임시로 넣어야 실제 반영 여부를 검증할 수 있다. Next.js가 `.env.local`을 읽게 하려면 dev 서버 재시작 필요. **검증 끝나면 반드시 `.env.local` 삭제** — 남겨두면 다음 리뷰가 로컬 백엔드에 의존하게 된다.
- 포트 3000이 이미 다른 프로세스(PID)에 점유돼 있으면 Next.js가 자동으로 3002 등으로 올라가면서 안내 로그에 `PID`와 `taskkill /PID <pid> /F` 명령을 출력해준다. Windows Git Bash엔 `lsof`가 없으므로 이 안내대로 `taskkill //PID <pid> //F`(슬래시 2개)를 쓸 것.
