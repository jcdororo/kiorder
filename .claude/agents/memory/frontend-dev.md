# frontend-dev 누적 경험치

이 파일은 `frontend-dev` 역할이 kiorder를 구현하며 축적한 지식이다. 매 작업 시작 시 읽고, 새로 배운 것을 아래에 이어서 기록한다.

## 병렬 작업 시 절대 규칙 (실제로 사고날 뻔했던 부분)

여러 에이전트가 동시에 작업할 때 **같은 파일을 수정하면 서로 덮어쓴다.** 2026-08-04에 컴포넌트 3개를 병렬 위임하며 확인: 신규 파일 생성만 병렬로 하고, 기존 페이지에 연결하는 작업은 오케스트레이터가 순차 처리하는 방식으로 회피했다. **프롬프트에 "이 파일은 건드리지 마라"는 지시가 있으면 반드시 지킬 것.**

## 이 프로젝트 특유의 패턴

### 상태 초기화는 useEffect보다 key 리마운트
컴포넌트가 상시 마운트되어 내부 state가 재사용되는 경우(다이얼로그 등), `useEffect`로 리셋하면 커밋 이후 실행이라 첫 프레임에 이전 값이 남는다. `key`로 리마운트시키는 게 정석이되, **key가 실제로 매번 바뀌는지 확인할 것** — `key={item?.id ?? "new"}`는 "추가" 케이스에서 항상 `"new"`라 리마운트가 안 된다. 열림 상태를 key에 포함시키는 식으로 해결(`MenuFormDialog` 참고).

### 훅 경계
서버 데이터·파생값·뮤테이션 → `hooks/`. 다이얼로그 open, 선택값 같은 UI 로컬 상태 → 페이지/컴포넌트. 훅에서 UI 뒷정리를 하지 말고 `{ onSaved }` 같은 콜백으로 호출부에 위임한다(`useOwnerMenu`, `usePosOrders` 패턴).

### 컴포넌트 자기완결성
form처럼 내부 상태가 복잡한 UI는 페이지가 상태를 끌어올리지 않고 컴포넌트가 통째로 소유한다. 페이지는 "언제 열지 / 무엇을 저장할지"만 안다.

## 검증 루틴
- `cd frontend && npx tsc --noEmit` — 완료 보고 전 반드시 통과시킬 것
- 화면이 바뀌었으면 육안 확인까지가 안전하다(Playwright 방식은 `.claude/agents/memory/ux-reviewer.md` 참고)
